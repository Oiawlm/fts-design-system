# 基础·海拔与材质（Elevation & Material）

> **一句话定位**：海拔与材质的原子规则——阴影隔离原则与三层结构、共享冻结实例、深浅主题阴影参数差异化、系统材质壳与不透明回退、对话框单壳；数值只是示例，权威快照在 `tokens/color.tokens.json` 的 shadow 组与 `tokens/dimension.tokens.json`。**来源**：源项目 1.72.0 基线（commit `bba9b4e`）设计规范层级章与窗口材质章＋两本主题字典阴影资源，经 TOKEN-MAP-V1（对账 [2026-11-fts-v1.72.0.md](../../reference/extractions/2026-11-fts-v1.72.0.md)） §3.1 映射。**日期**：2026-11-11。**行数预算**：≤300 行（现 76 行）。交叉引用：[color.md](color.md)（阴影色键与表面键）、[shape-and-spacing.md](shape-and-spacing.md)（壳圆角键）。

## 一、普适规则

1. **阴影隔离原则（第一法则）**：投影效果**永不进入承载文字的子树**——带投影效果的元素会把整个子树渲染进中间位图并强制关闭亚像素文字渲染（正文发糊的主因）。阴影必须是**不含内容的独立图层**。
2. **三层结构**（阴影隔离的标准解法）：
   - **根容器**：承载外距与悬停抬升（渲染位移），**不携带任何效果**；
   - **阴影层**：与内容面同形状的不透明底＋共享投影效果——**不承载内容、不参与命中测试**；
   - **内容面**：不透明表面底＋描边＋焦点态，**不得携带效果**。
   三层各司其职：效果只落在阴影层，文字只落在内容面。
3. **共享冻结单一实例**：同类表面共用一枚冻结（不可变、免重绘）的投影资源，**不逐元素实例化**——虚拟化长列表里逐卡片实例化效果是性能反模式。
4. **深浅主题阴影参数差异化**：投影几何参数（偏移/模糊/扩散）两主题同值，**颜色与不透明度随主题分档**——浅色主题用低不透明度深灰投影，深色主题用更高不透明度纯黑投影（示例值：`color.shadow.card-opacity` 浅 0.12／深 0.35）；不透明度单列成 token（不折叠进色值 alpha），供程序侧与 Web 投影消费。
5. **海拔语义克制**：一个体系只需要一档卡片海拔（单一投影参数集）；「层级感」更多由表面明度阶（见 [color.md](color.md) §一.1）承担，不是层层加码投影。悬停的「抬升」用**渲染位移**表达（示例值：`dimension.offset.card-hover-lift` −1px），**不实时改投影参数**。
6. **系统材质壳（可选能力）**：主窗可用系统级背景材质：半透明表面色调浮在系统材质上（示例值：约 80% alpha 的壳色，`color.material.window-shell-tint`）＋系统圆角＋沉浸式深浅标题；深浅主题切换时同步系统深色模式标志。**材质是锦上添花，不是依赖**。
7. **材质回退路径**：材质不可用（旧系统/平台不支持）必须回退到**不透明壳色**（`color.surface.window-shell`）——回退是设计内的第一公民路径，不是异常分支。
8. **对话框不用材质**：弹窗/对话框表面＝**不透明主题表面**（`color.surface.dialog`）＋系统级圆角与阴影（由窗口系统随圆角偏好自动生效，唯一来源）；禁止「透明背景＋外距挤圆角＋手工阴影」假圆角三件套，禁止给弹窗套材质。
9. **壳圆角同值自裁剪**：窗壳圆角由系统承载（窗体不自带圆角资源裁切），**内容层以同值圆角四角自裁剪**保证渲染与屏幕一致（示例值：8px，`dimension.radius.shell`）；不设第二个壳圆角数值；禁用区域裁切 API 与任何装饰性掩盖——圆角在任务栏停靠、多显示器、插拔与系统广播下保持恒定。

## 三、新项目落地要点

1. **三层结构先行**：写第一个卡片/浮面组件时就建「根/阴影层/内容面」三层模板；后续所有带阴影的表面复用该模板，效果只进阴影层。
2. **阴影资源单点**：投影定义放主题字典（或 token 镜像），冻结共享；组件样式引用资源键，不内联效果参数。
3. **双主题阴影成对交付**：浅/深各一枚效果资源（几何同值、色与不透明度分档）；token 层色与不透明度分列，平台镜像层才允许折叠。
4. **材质能力探测式接入**：主窗材质按「能力探测→成功上材质色调／失败回退不透明壳色」实现；回退路径纳入截图验收（旧系统形态也是交付面）。
5. **弹窗族单壳纪律**：所有对话框统一走不透明表面＋系统圆角/阴影；新弹窗不继承任何透明/材质设定。
6. **圆角对齐链**：窗壳圆角 token → 系统裁剪偏好 → 内容层自裁剪，三处同值联动；变更走同一 token。
7. **镜像锁定覆盖阴影**：锁定测试断言阴影资源存在、冻结、几何/色/不透明度与数值源一致——防「深浅字典各改一半」漂移。
8. **验收含发糊检查**：带阴影表面的文字截图放大检查亚像素渲染（隔离失效的症状是正文发糊，不是阴影消失）。

## 四、反例信号

- 投影效果直接挂在承载文字的容器上（正文发糊；这是最常见也最隐蔽的缺陷）。
- 每个卡片/条目实例化自己的效果对象（长列表滚动掉帧）。
- 深浅主题共用一套阴影参数（深色下轻飘飘/浅色下脏成一团）。
- 悬停用「加深阴影」表达（实时改效果参数触发重栅格化）。
- 透明背景＋margin 挤圆角＋手工阴影的假圆角弹窗；弹窗套材质/半透明。
- 材质失败无回退（旧系统黑底/白底裸奔）。
- 内容层圆角与系统裁剪圆角不同值（四角露直角或裁切内容）。
- 用区域裁切 API 或隐藏窗口装饰性掩盖中间态。
- 阴影层承载内容或参与命中（点击穿透错误/文字进位图）。
- token 层就把色与不透明度折叠成一个带 alpha 的色值（程序侧无法单独消费）。
