# 范式·自算拉伸填充网格（Stretch-Fill Grid）

> **一句话定位**：动作瓦片网格的几何引擎——列数由视口宽经钳制公式现算、余宽全部摊进瓦片宽（行满排总宽恒等于视口、无量化死区）、全部几何出自单一计算源；配套「列数策略」扩展点与滚动恢复无关的纯静态排版。**来源**：源项目 1.72.0 基线（commit `bba9b4e`）启动表面网格数学与承载面板，经 TOKEN-MAP-V1（对账 [2026-11-fts-v1.72.0.md](../../reference/extractions/2026-11-fts-v1.72.0.md)） §3.2 映射；实现锚点见本文「fts 溯源与可移植要点」。**日期**：2026-11-12。**行数预算**：≤350 行。交叉引用：[tile.md](tile.md) 的瓦片结构、[scrollbar.md](scrollbar.md) 的视口几何。

## 一、问题与适用

**要解决的问题**：

1. **量化死区**：定宽瓦片＋换行面板的排布在末列留出「装不下一个瓦片」的余白带——视口越宽死区越显眼，且死区位置随列数跳变。
2. **双几何源漂移**：「公式算宽度」与「面板再排版」两套口径并存时，同一视口下公式值与实际值互相追赶，出现列数抖动。
3. **自引用回写**：把布局结果回写进参与布局的自身属性（如滚动回调里改自身宽），形成反馈回路——窗口缩放时几何震荡，是回归 bug 的经典结构。

**适用**：等高、近似等宽（下限保障）的条目网格；条目数有界（数百级）；要求行满排总宽精确等于视口。**不适用**：异构尺寸瀑布流（用多列流布局）；无限滚动大数据集（需要虚拟化，见 §五.6）。

## 二、结构分解

1. **输入常量（全部单源）**：瓦片宽下限 84、瓦片高 100、沟道 8、节距＝下限宽＋沟道＝92（最小单元格）、列数下限 3、上限 6（示例值：`dimension.tile.*`，见 [tile.md](tile.md) §四）。
2. **列数公式（钳制取整）**：`n = clamp( floor((A + 沟道) / 节距), 3, 6 )`，A＝视口宽。把沟道加进分子使「恰能容纳 n 个瓦片＋n−1 条沟道」的边界落在整数格上——n 列的最小可行视口恰为 `n×84+(n−1)×8`，边界处瓦片宽恰为下限。视口 0（窄轨/收起期）与非有限输入走列数下限兜底，不产生非法值。
3. **瓦片宽公式（余宽全摊）**：`w = (A − 沟道×(n−1)) / n`——余宽摊进每个瓦片，行满排总宽精确等于视口、零死区；域内构造保证 `w ≥ 84`（下限），域外（视口 0/极窄）返回值钳制非负。
4. **单一几何计算源**：列数与瓦片宽的唯一计算来源是上述两个纯函数；承载面板在测量/排列两阶段直接调用现算并自行排版——不存在「公式限宽＋面板再量化」第二口径，也不存在把布局结果回写自身宽度的自引用结构。
5. **承载面板（自定义排列）**：测量阶段按视口宽算列数与瓦片宽、以「瓦片宽×瓦片高」约束逐子测量、总尺寸＝列满排宽×（内衬×2＋行数×高＋行间沟道）；排列阶段行优先（行号＝下标÷列数、列号＝取模）逐子落位，末行不满靠左。瓦片不自带外距——沟道由排版间距承载。
6. **列数策略扩展点**：默认自适应＝公式；固定档（3–6）与视口无关恒等于档位值、瓦片宽仍由摊分公式给出（行满排无死区不变；窄视口下大列数可把瓦片压到下限以下——显式选择的语义，允许）。策略经依赖属性下发，赋值即失效重测、下一次布局即新策略；面板未激活期由表面激活路径回放当前偏好。
7. **视口内衬**：内容顶/底各留 token 内衬（随内容滚动），吸收瓦片渲染变换（悬停上浮/确认脉冲）的溢出、护住首/末行圆角（几何动机见 [tile.md](tile.md) §四）；空面板不留内衬（空态是兄弟元素，面板自身零高度）。

## 三、状态与动效

网格本体是**纯静态排版**：列数/瓦片宽变化（窗口缩放、策略切换）直接进入下一次布局，不做几何过渡动画——条目微交互（悬停/按压/脉冲/落位/交错入场）全部是瓦片层的渲染变换，不回流网格几何（[《动效》](../motion.md)「编排」：交错入场步进 40ms、封顶 min(i,8)，见 [tile.md](tile.md) §三；[《形状与间距》](../foundations/shape-and-spacing.md)「位移与间距分立」）。策略切换＝失效重测：无过渡帧、无跳帧补算特例；视口 0（收起期）由布局系统自然承载（量出 0 宽、展开后自动重测）。

| 节距（最小单元格） | 92px＝84＋8 | dimension.tile.pitch（派生，公式记于 $description） |

派生关系（成文不入档，公式即约束）：n 列最小可行视口＝`n×84+(n−1)×8`；行满排总宽＝`n×w+(n−1)×8`＝视口宽（恒等式，摊分公式的直接推论）；内容总高＝`2×内衬＋行数×高＋(行数−1)×沟道`。**几何随视口连续变化、列数阶梯跳变**：视口缩过列数边界时整行重排——这是公式的确定行为，不是缺陷；抖动只会在双几何源/自引用结构下出现。

## 五、已知反例

1. **「公式限宽＋面板再量化」双口径**：公式算出一版宽、面板按自身规则再排一版——两源随主题/DPI/字体渲染差异漂移，列数忽多忽少。几何只能有一个计算源。
2. **滚动回调回写自身宽**：`ScrollChanged` 里改参与布局的自身宽度属性＝反馈回路（缩放窗口时几何震荡的历史回归结构）。回写参与布局的属性一律禁止。
3. **居中网格**：行满排总宽＝视口的设计下，居中即制造左右死区——网格拉伸填充、末行左对齐。
4. **瓦片自带外距**：外距参与摊分公式外的第二套间距，行满排恒等式破坏——沟道只由排版承载。
5. **固定档强行钳回下限**：固定列数是显式用户选择，把瓦片宽钳回下限会让行满排出现死区——尊重选择、摊分到底。
6. **给有界数据集上虚拟化**：条目数已有上限（数百级）时虚拟化引入容器再生/状态保持复杂度，收益为负——有界性由数据上限承载，网格保持简单。（真正的长列表用分层状态卡片＋虚拟化宿主，见 [card.md](card.md)。）

**可移植要点**：

- **CSS 原生即单源**：`grid-template-columns: repeat(auto-fill, minmax(84px, 1fr))` 就是「钳制列数＋余宽全摊」的浏览器实现——几何计算源天然唯一（浏览器布局器）。列数上下限（3–6）需容器查询或一小段脚本钳制；固定档＝`repeat(n, 1fr)`。
- **摊分恒等式是验收断言**：`n×w+(n−1)×gutter === viewportWidth` 可写成布局测试——移植后用它守住「无死区」不被回归。
- **禁止自引用回写**在 Web 的对应：不要在 `ResizeObserver` 回调里设置影响被观测盒尺寸的属性；需要重算时改数据、让布局单向往下走。
- **自定义面板（WPF）**：`Panel.MeasureOverride/ArrangeOverride` 直算是「单一几何源」的最强形态；若不用自定义面板，务必让宽度公式只从视口读入、绝不从自身布局产物读入。
- **视口内衬**：滚动容器内容块的 `padding-block`（随内容滚动），不是容器装饰层。
