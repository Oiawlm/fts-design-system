# 范式·空状态构图（Empty State）

> **一句话定位**：把「没有内容」当一种被设计的状态——图标＋标题＋副文案三件套居中构图、无 CTA 默认、命中穿透不挡操作、文案按二维矩阵单点派生、可见性由唯一求值点收敛全部触发路径；四个宿主一套语言。**来源**：源项目 1.72.0 基线（commit `bba9b4e`）空状态宿主族与文案矩阵，经 `handoff/2026-11-11-bootstrap/TOKEN-MAP-V1.md` §3.4 映射；实现锚点见本文「fts 溯源与可移植要点」。**日期**：2026-11-12。**行数预算**：≤350 行。交叉引用：[card.md](card.md) 的列表宿主、[scrollbar.md](scrollbar.md) 的宿主几何。

## 一、问题与适用

**要解决的问题**：

1. **「空」有多种，一种构图说不清**：内容桶真空（从未收集）、搜索无匹配（有内容但被筛掉）、分组被过滤成空（视图空而非内容空）、当日无记录（输入面空）——混淆它们会给出错误引导（对「视图空」喊「快去添加」是驴唇不对马嘴）。
2. **CTA 泛滥**：每个空态都放一个大按钮——多数空态的进入路径并不是按钮（拖入/输入/等待采集），CTA 只在该路径真实存在时才有意义。
3. **多宿主多更新点**：空态可见性由「表面切换/集合增删/默认接收迁移/搜索进出/过滤」多条路径影响——更新点分散必然漏路径，两段空态文字同格叠加是这类实现的实证级 bug。
4. **空态挡操作**：居中大块若无命中穿透，挡住拖放落点与点击——空态是信息层不是交互层。

**适用**：任何「集合可能为空」的表面——列表、网格、输入面、过滤视图。**不适用**：加载中（用加载态，不是空态）；错误态（错误有修复动作，语言不同）。

## 二、结构分解

1. **三件套构图（居中）**：图标（系统图标字体字形、次级色、36px）→ 标题（正文字号、半粗强调档、主文本色、上距 10 下距 2）→ 副文案（说明字号、次级色、可换行）。图标尺寸属字形尺寸族（豁免于文本字号档），标题/副文案落排版档位（《排版》字号档全表）。
2. **四个宿主一套语言**：
   - **内容桶空态**（图标＋标题＋副文案，无 CTA——进入路径是复制自动收集/拖入，无显式添加动作）；
   - **搜索/过滤空结果**（标题按来源切换文案；搜索分支＝标题＋「清空筛选」CTA；分组过滤分支＝标题＋副文案引导、无 CTA——轨在场且被过滤 chip 高亮，退出通道充足，引导由文案承载；两分支互补三件套：CTA 与副文案互斥退位）；
   - **记录空态**（图标＋标题＋副文案覆盖在输入面行内，编辑器本身就是动作面，无 CTA；「当日无内容」以编辑器文本为唯一事实源）；
   - **启动面空态**（唯一带 CTA 的宿主——进入路径「右上＋添加」真实存在，CTA 与工具行共用同一入口）。
3. **命中穿透**：信息性空态一律关闭命中测试——点击/拖放穿透回底下列表或输入面（兄弟层不截获事件）；CTA 宿主除外（按钮自身可命中）。空态声明在宿主内容之后＝同格渲染其上，但不与内容争用（可见性谓词互斥）。
4. **文案二维矩阵（单点）**：标题/副文案由 (内容分类, 是否默认接收) 二维查表穷尽派生——默认接收桶＝「复制自动收集」话术、非默认桶＝「拖入收集」话术、记录臂＝「直接输入」话术；矩阵穷尽具名值、无兜底臂（新增分类漏映射＝编译期失败而非运行期空白）。启动面空态文案独立于矩阵（宿主自持）。
5. **唯一求值点**：一个函数从当前状态一次算出**全部**空态宿主的可见性与文案并应用；全部状态迁移路径（表面切换、集合增删、默认接收迁移、搜索进出、过滤单点）都汇聚调用它。求「求值点唯一」不求「调用次数最少」——同路径重复调用纯求值幂等无害。集合事件可能来自后台线程，非 UI 线程进入统一封送回 UI 线程再碰元素。
6. **求值时机取视图侧**：订阅视图集合事件（视图内部状态更新完成后发出）而非源集合事件——源事件里同步求值会读到尚未消化变化的过期视图（时序性缺席 bug 的根因）。
7. **宿主互斥**：同格多空态（内容桶/搜索/记录）由求值点谓词结构性互斥——搜索空态让位内容桶空态、面板真空由专属空态承载；不靠「后写者胜」。

## 三、状态与动效

空态**默认零动效**：可见性即时切换，无入场淡入、无图标动画——空态的使命是解释状态，不是吸引注意；它是页面上唯一「越安静越好」的元素（《动效》「原则」：动效永不作信息唯一载体）。涉及的态切换全部即时：

| 迁移 | 行为 |
|---|---|
| 空→非空 | 空态即失可见性（同一求值点内完成，无过渡帧） |
| 非空→空 | 即显；文案随矩阵重派生（只在可见时重算，不可见期残留文案无意义） |
| 默认接收迁移 | 文案换格（矩阵第二维翻转），可见性不变 |
| 搜索进出 | 搜索空态与内容桶空态让位交接，同格互斥 |
| 主题切换 | 图标/标题/副文案色随语义键整本替换（《配色》「语义色分组」） |

## 四、几何与尺寸

| 项 | 示例值 | 归属 |
|---|---|---|
| 图标字形尺寸 | 36px | 字形尺寸族（豁免文本字号档，《形状与间距》登记制口径） |
| 标题字号 | 14px | typography.size.body |
| 副文案字号 | 12px | typography.size.secondary |
| 标题强调 | 半粗单档 | typography.weight.emphasis |
| 标题上/下距 | 10px / 2px | 宿主节奏字面量（语义异质不 token 化，《形状与间距》「间距节奏」） |
| CTA 内边距 | 10×3 / 14×5（按宿主） | 结构字面量 |
| 构图对齐 | 水平/垂直居中于内容区 | 结构约定 |

几何纪律：空态**不占布局格**——与内容同格叠加、靠互斥可见性；这保证空态出现/消失不牵动周围结构（宿主骨架恒定）。

## 五、已知反例

1. **逢空必 CTA**：按钮只属于「进入路径＝显式动作」的空态；对拖入/输入/等待型空态放按钮是错误引导。
2. **两分离更新点**：空集臂与内容桶臂各更各的——过滤路径只重评一个，两段空态文字同格叠加（用户实证级 bug）；求值点必须唯一且覆盖全部路径并集。
3. **空态截获命中**：挡住穿透点击/拖放——信息层关闭命中测试是硬规则。
4. **文案散写各宿主**：同一语义在不同宿主各自硬编码——改一处漏三处；矩阵单点派生。
5. **兜底臂兜住新分类**：查表加 default 分支让漏映射静默通过——穷尽具名值＋编译期失败（新增分类必须显式决定话术）。
6. **空态入场动画**：淡入/弹跳吸引注意，空态越抢眼越像错误——零动效。
7. **源集合事件同步求值**：读到未消化完的过期视图（空态缺席时序 bug）；订阅视图侧事件或延后一拍。
8. **残留文案常驻重算**：不可见期反复派生文案——只在可见时重算。
9. **把「加载中」画成空态**：两种状态语义不同（等待 vs 无物），混用让用户误判终态。

**可移植要点**：

- **纯结构零翻译**：三件套构图、命中穿透（CSS：`pointer-events: none`）、居中变体、四宿主互斥——任何栈直接照搬。
- **文案矩阵**＝一个纯函数 `(category, isDefaultCapture) => {title, hint}`——Web 用对象表/穷尽 switch＋类型系统（新分类编译期报错）同样可达成。
- **唯一求值点**＝「单一 derive 函数＋全部 mutation 路径调用」——前端框架里即「所有状态变更收敛到一个 store selector / 派生函数」，杜绝各组件各自 watch 各自算。
- **视图侧时机**：框架响应式更新天然解决了「源事件 vs 视图消化」时序（派生在渲染前跑）；无框架环境手动实现时记得这条教训。
- **CTA 判定**是产品决策不是视觉决策：先回答「这个空的进入路径是什么」，再决定按钮有无。
