# 范式·单壳对话框（Single-Shell Dialog）

> **一句话定位**：一组小模态对话框共用一个壳——不透明表面＋1px 描边＋表面档圆角，圆角与阴影的唯一来源是窗口系统级能力（内容层同值自裁剪），系统不给就直角回退，全程零手工效果；一个壳消灭逐窗各自为政的壳漂移。**来源**：源项目 1.72.0 基线（commit `bba9b4e`）对话框壳样式与窗口效果实现，经 `handoff/2026-11-11-bootstrap/TOKEN-MAP-V1.md` §3.1 映射；实现锚点见本文「fts 溯源与可移植要点」。**日期**：2026-11-12。**行数预算**：≤350 行。交叉引用：[card.md](card.md) 的阴影隔离原则、《层级与材质》「对话框单壳不用材质」。

## 一、问题与适用

**要解决的问题**：

1. **壳漂移**：应用里五六个小对话框（地址输入、应用选择器、编辑目标、多选器……）各写各的壳——底色、圆角、描边、阴影渐渐长得不一样，主题切换后更是五彩缤纷。
2. **假圆角三件套的代价**：框架元素自绘圆角窗口的传统手法是「分层透明背景＋外扩边距装圆角＋自绘投影」——性能差、锯齿、投影与裁剪打架、边缘漏背景。
3. **系统不给圆角时的破相**：远程会话/旧系统下系统级圆角缺失，固定圆角的壳会呈现「内容方角但边框圆角」的破相——回退必须有设计。

**适用**：短生命周期、少量控件的模态对话（输入一行、选一项、确认一次）；一个产品内复数个此类窗口。**不适用**：常驻工具面板（不是对话，用主表面语言）；需要系统材质透明壳的场景（那是窗壳材质范式，对话框明确不用——《层级与材质》「对话框单壳不用材质」）。

## 二、结构分解

1. **一个壳，多窗复用**：全部小对话框的根都是同一个壳样式——不透明对话框表面色（独立语义键，与卡片表面色区分）＋1px 默认描边＋表面档圆角（示例值：`dimension.radius.surface`）＋统一内容内边距 24。壳即语言：新对话框不设计壳，直接住进来。
2. **圆角与阴影唯一来源＝窗口系统**：圆角由窗口管理器偏好（系统级裁剪）给出，系统阴影随圆角偏好自动生效；**窗口玻璃帧厚度归零**（不透底、不给分层透明留口子）；内容壳的圆角与系统裁剪值**同值自裁剪**——渲染位图与屏幕裁剪一致（《层级与材质》「壳圆角同值自裁剪」）。壳自身不携带任何位图效果——阴影隔离原则同 [card.md](card.md) §二.1，但这里更进一步：连阴影都不自绘。
3. **深浅标题同步**：应用深色模式时同步设置沉浸式深色标题属性——标题栏文字/边框随主题，不出现浅标题配深内容。
4. **直角回退（可用性兜底）**：系统圆角偏好设置失败（远程会话/旧系统）时，把壳圆角**归零**——回退为完整的直角矩形（1px 边框完整），不是「保留圆角祈祷」也不是第二套装饰。回退判定按位返回值，逐窗应用。
5. **内容层职责**：壳只管框；内部控件走主题样式族（输入框/按钮/列表各自单源），命中区规格按类型学登记（《交互状态》「类型学」命中区行——对话框内文字钮高覆写一档、退出钮再高半档，均登记不入档）。

## 三、状态与动效

壳本体**零装饰动效**：无入场缩放、无壳级投影动画——对话框的价值是「即刻可交互」，任何入场动画都在推迟这一点（《动效》「原则」：动效永不作信息唯一载体，对话的载体是对话本身）。涉及的态只有：

| 状态 | 行为 |
|---|---|
| 主题切换 | 壳表面/描边色随语义键整本替换（对话框表面键），深浅标题属性同步——即时 |
| 内部控件禁用 | 控件禁用档灰化（示例值：`motion.opacity.control-disabled`），壳不参与（《交互状态》「禁用档」） |
| 减动效 | 无壳级动画可退化；内部控件的悬停/按压反馈按《动效》「减动效」统一退化 |
| 危险确认项 | 危险语义色文字/描边（删除类确认），颜色即语义不靠动画 |

## 四、几何与尺寸

| 项 | 示例值 | token 路径 / 归属 |
|---|---|---|
| 壳圆角 | 8px | dimension.radius.surface（表面档判定：承载内容的表面） |
| 内容内边距 | 24px | 结构字面量（壳级节奏，随壳样式登记） |
| 描边 | 1px | 结构约定（默认描边语义键） |
| 壳表面色 | 语义键 | color.surface.dialog（与卡片表面色分立的独立身份） |
| 文字钮高（对话框覆写） | 32px | 命中区规格按类型登记，不入档（《交互状态》「类型学」） |
| 退出钮高 | 34px | 同上 |

尺寸纪律：对话框窗口自身尺寸属**结构性尺寸**（结构不为内容让步，不 token 化）；「一个壳」约束的是视觉语言，不是窗口几何。

## 五、已知反例

1. **假圆角三件套**：分层透明背景＋外扩边距装圆角＋自绘投影——性能/锯齿/漏背景三连；撤除三件套、改走系统级圆角是本范式确立的直接动因。
2. **第二套假阴影**：回退时补一层自绘投影「保住观感」——观感没保住，还制造了双阴影来源；直角＋边框就是回退态的完整设计。
3. **失败时保留固定圆角**：内容方角＋边框圆角的破相（圆角描边内的四个透明角）——失败必须连壳圆角一起归零。
4. **逐窗自制壳**：每个对话框一份底色/圆角/内边距——复数窗口必然漂移；壳样式单源，新窗只带内容。
5. **对话框用系统材质/半透明**：模态对话要的是隔绝与稳定——不透明表面承载；材质是主窗壳的语言（《层级与材质》「系统材质与回退」）。
6. **壳级效果（模糊/投影）**：同 [card.md](card.md) §五.1 的子树位图问题，且对话框文本密度高——零效果。
7. **入场动画（缩放/弹跳）**：推迟可交互时刻；若框架默认给了，关掉。

**可移植要点**：

- **Web 是降维场景**：浏览器里 `border-radius`＋`box-shadow` 天然无三件套问题——`<dialog>` 元素或一个壳组件（表面色＋1px 描边＋8px 圆角＋24px 内边距）就是全部；「一个壳多窗复用」翻译为「一个壳组件多对话框复用」，价值不变。
- **阴影唯一来源**在 Web 的对应：投影定义在壳组件单处（或设计令牌），对话框内容永远不带自己的投影——防漂移的本质是单源，不是系统级与否。
- **回退思维的移植**：Web 无「系统不给圆角」，但有等价的降级链——`forced-colors` 模式下投影/圆角失效时应退到「边框完整的直角卡」而不是花哨补偿；先想好降级态再写常态。
- **深浅标题同步**：对应 `color-scheme` 属性随主题切换——让浏览器原生部件（滚动条/表单控件）跟随，一行即可，但要有。
- **WPF 特有需翻译**：系统级圆角（DWM 窗口圆角偏好）与窗口玻璃帧厚度归零是 Windows 机制；Web/Compose/SwiftUI 上「系统裁剪 vs 元素自裁剪」的辨析不存在，直接元素圆角＋同值内容裁剪（`overflow: hidden`）即可。
