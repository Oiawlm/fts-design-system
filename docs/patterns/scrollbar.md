# 范式·Overlay 瘦滚动条（Overlay Slim Scrollbar）

> **一句话定位**：滚动条不占布局宽的完整方案——单格叠加模板让条带悬浮于内容右缘、瘦拇指悬停经叠加层交叉淡入展宽换色、列表宿主与文本输入宿主两套挂接同构，配套「measure-then-scroll 两轮布局恢复」消灭切换时的闪现与跳变。**来源**：源项目 1.72.0 基线（commit `bba9b4e`）滚动条样式族与滚动恢复实现，经 TOKEN-MAP-V1（对账 [2026-11-fts-v1.72.0.md](../../reference/extractions/2026-11-fts-v1.72.0.md)） §3.1/§3.3 映射；实现锚点见本文「fts 溯源与可移植要点」。**日期**：2026-11-12。**行数预算**：≤350 行。交叉引用：[card.md](card.md) 的列表宿主、[grid.md](grid.md) 的视口几何。

## 一、问题与适用

**要解决的问题**：

1. **滚动条出现/消失改变内容几何**：默认模板给滚动条留独立布局列——打满一屏时条带突然占宽（系统样式还有宽度下限），列表卡片宽度跳变、流式文本全文重排换行（「输入到一定程度滚动条出现，已输入文字突然整体换行」是此类实现的典型报障）。
2. **系统滚动条与语言不匹配**：原生滚动条的宽度、拇指色、悬停行为不在设计体系内，主题切换后成为异物。
3. **切换/过滤后滚动位置恢复闪跳**：内容换绑后同步恢复会滚到错误偏移（可滚动高度还是旧数据的陈旧值），异步恢复又常见「先顶到 0 再跳下去」的双帧闪现。

**适用**：一切需要滚动反馈又不容内容几何漂移的表面——密集列表、大篇幅文本输入面、共享设置视口。**不适用**：永远不满一屏的内容（不需要滚动条就不需要本范式）；需要横向精确定位的宽表格（横向条参与布局语义另议）。

## 二、结构分解

1. **单格叠加模板（内容宿主＝滚动条宿主）**：滚动视口模板为单格网格——内容台与垂直/水平两条滚动条同格叠放，条带贴右缘/底缘悬浮其上、**不占布局列**；内容台几何与滚动条可见性解耦。条带的最小宽/高压到 0，挤掉系统滚动条样式的尺寸下限（那是「不占宽」失败的技术根因）；可见性语义保持 Auto（需要时才出现），不引入自动隐藏定时器。
2. **三部件齐全**：透明轨道按钮（翻页点击区域）＋瘦拇指＋（水平向同理）——键盘滚动与翻页语义必须随模板保留，三个命名部件与属性透传缺一不可（虚拟化与键盘滚动的生命线）。
3. **瘦拇指＋悬停展宽层**：拇指基宽 4、最小高 24、圆角 2（线状件派生＝宽一半，[《形状与间距》](../foundations/shape-and-spacing.md)「派生三族规则」）；悬停不改基宽——在拇指内叠加一个宽 6、圆角 3 的悬停层（悬停色）交叉淡入，视觉上「展宽＋换色」一步完成，几何与颜色解耦于单一属性（[《交互状态》](../interaction-states.md)「hover 双轨」层淡入轨道；交叉淡入时长＝悬停反馈档）。
4. **两宿主挂接（同构派生）**：
   - **列表宿主**：列表控件资源作用域内以「基于模板的隐式样式」挂接——只作用于该列表内部生成的滚动视口，不做全局隐式样式（避免波及其余滚动表面）；
   - **文本输入宿主**：从主题输入框基样式**派生**——只重写模板把内容宿主直引同一滚动模板，画刷/圆角/聚焦环等纯样式单一来源不变；唯一模板差异是内边距从内容台外边距改为透传（条带贴满宽右缘、瘦条落在内边距带内与文字零相交）。
5. **条带落位约定**：条带宽 8 落在宿主内容右缘的内缩/内边距带（12）内——与内容零遮挡是该范式的几何前提，宿主侧必须为条带留出这条「本来就有」的带。

## 三、状态与动效

| 状态 | 视觉 | 动效 |
|---|---|---|
| 拇指悬停 | 6px 悬停层交叉淡入（展宽＋换色观感） | 167ms（示例值：`motion.duration.hover-feedback`） |
| 出现/消失 | Auto 语义——需要时才出现 | 无动画（可见性即时）；不引入自动隐藏定时器 |
| 主题切换 | 拇指/悬停色随语义键整本替换 | 即时（[《配色》](../foundations/color.md)「语义色分组」滚动条组） |
| 减动效 | 悬停展宽直达终态 | [《动效》](../motion.md)「减动效」 |

**两轮布局恢复（measure-then-scroll）**——切换分类/过滤后恢复滚动位置的专用节：

1. **按上下文保存**：离开某分类/表面前保存其垂直偏移（保存粒度＝内容分组，不是全局一个值）。
2. **恢复时序**：换绑后**先强制完成一轮布局**建立真实可滚动高度（换绑瞬间的旧高度是陈旧值，直接滚会被钳错）→ 按保存值钳制后**滚动到目标偏移并再完成一轮布局**（完成容器生成）。两轮布局都发生在内容淡入启动**之前**——首帧直接落在最终偏移，不存在「偏移 0 生成→首帧→再滚→再生成」的闪现、跳变与首帧后重活。
3. **版本号取代**：每次恢复递增版本号，在途的异步恢复（如搜索跳转）被新恢复取代——同屏只有一次恢复生效。
4. **幂等短路**：当前偏移与目标差 ≤0.5px 时不再滚动——避免无意义的布局扰动。

## 四、几何与尺寸

| 项 | 示例值 | token 路径 |
|---|---|---|
| 条带宽 | 8px | 结构字面量（隐式滚动条样式给出，压掉系统下限） |
| 拇指基宽 | 4px | 结构字面量（模板样式） |
| 拇指悬停层宽 | 6px | 结构字面量（叠加层） |
| 拇指最小高 | 24px | 结构字面量（可拖性下限） |
| 拇指圆角 | 2 / 3（派生＝宽/2） | 派生不入档（《形状与间距》「派生三族规则」） |
| 拇指色/悬停色 | 语义键 | color.scrollbar.thumb / color.scrollbar.thumb-hover |
| 悬停展宽时长 | 167ms | motion.duration.hover-feedback |

条带宽 8 与宿主内缩带 12 的关系是**设计约束**：条带必须整体落在宿主既有留白带内（8＜12），任何新宿主接入前先核对其右缘留白。

## 五、已知反例

1. **独立布局列＋系统宽度下限**：默认模板的原罪——出现/消失在全宽与全宽−系统条带宽之间跳变，列表卡片几何漂移、流式文本全文重排（[card.md](card.md) §五.9 同案）。
2. **稳定留槽（常显占位）**：给滚动条永远留一列宽度消灭跳变——牺牲水平空间且「不满一屏也有槽」；仅小面积编辑器可接受，大输入面/列表应走 overlay。
3. **自动隐藏定时器**：延时淡出＋收起手势——复杂度高且与「需要时才出现」的 Auto 语义重叠；本范式明确不引入。
4. **全局隐式样式挂接**：一个模板吃掉应用里所有滚动表面——记录编辑器等派生面失去差异能力；作用域挂接（列表资源域/派生样式）是正解。
5. **基样式整体复制改模板**：文本宿主复制整个输入框样式再改——画刷/圆角/聚焦环出现第二来源；派生＋只重写模板。
6. **拇指直接改宽**：悬停改基宽——命中区随悬停变化、圆角需同步分支；叠加层交叉淡入一步到位。
7. **同步恢复不等布局**：换绑后立即滚——被陈旧高度钳错位置；也不允许「滚了再说」的异步补滚（首帧闪现）。两轮布局恢复是确定性方案。
8. **滚动条作视觉装饰**：不满一屏强显条带/加轨道底色——滚动条只承载滚动反馈，不是表面装饰。

**可移植要点**：

- **CSS 现代等价**：`scrollbar-gutter: stable` 解决「跳变」但占槽（留槽反例的官方化）；真正的 overlay 观感用 `overflow: auto`＋自定义滚动条（`::-webkit-scrollbar` 系或标准 `scrollbar-width: thin`＋`scrollbar-color`）——条带不占内容盒宽由浏览器保证。悬停展宽在标准属性下不可得，接受「换色不展宽」或用容器查询近似；**别为展宽把条带改成自绘浮层**（失去原生滚动手感与无障碍语义）。
- **瘦拇指配色**直译：`scrollbar-color: var(--color-scrollbar-thumb) transparent`，悬停色浏览器不支持则舍去——拇指色已是体系语义键，跨平台保底。
- **两轮布局恢复的 Web 直译**：`element.scrollTo` 前先 `await` 一帧布局（或读 `element.scrollHeight` 确认 extent 更新）；首帧前恢复＝在内容容器仍隐藏/透明时完成滚动再显形。版本号取代在 Web 同样必要（快速切换路由/过滤时旧异步恢复会晚到覆盖）。
- **WPF 特有需翻译**：命名部件（PART_*）契约是 WPF 模板机制；「压掉系统下限」的 MinWidth=0/MinHeight=0 细节无 Web 对应；作用域隐式样式挂接 ≈ CSS 选择器作用域（只选列表容器后代，不写全局 `*`）。
