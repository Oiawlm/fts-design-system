# adoption-workflow：新项目套用工作流（八步）

> **一句话定位**：任何新软件或网站项目套用本设计体系的总纲——从读哲学到收尾验收的八步流程，每步含目标/动作/产出/自检；平台细节由 [wpf.md](wpf.md) 与 [web.md](web.md) 展开，本文不重复栈内实现。
> **来源**：skill「fts-style-system」SKILL.md 八步工作流（直系前身）通用化扩写；token 键名与路径以 `tokens/` 四件、`platforms/` 镜像为准（映射权威 TOKEN-MAP-V1）。
> **日期**：2026-11-11　**行数预算**：≤320 行

## 一、定位与读法

1. 本文是「从读到用」的入口：四层架构（`tokens/` → `platforms/` → `docs/` → `skill/`）中，哲学/基础/动效/范式各篇回答「为什么与是什么」，本文回答「按什么顺序做」。
2. 八步即依赖顺序：先立数值源（步 2/3），再消费（步 4/5），最后验收（步 6/7/8）；跳步的典型代价＝数值双源与范式漂移。
3. 每步四段固定：**目标**（消灭什么风险）→ **动作**（做什么）→ **产出**（结束时存在什么）→ **自检**（凭什么判定通过）。
4. 数值口径：本文出现的数值一律为示例值（括注 token 路径），权威是 `tokens/` 四件（W3C DTCG 快照）；新项目按自身品牌重新推导（步 2）。

## 二、八步工作流

### 步 1｜读哲学，定范围

- **目标**：与团队对齐「这套体系解决什么问题」，圈定覆盖面，避免全盘照抄或范围蔓延。
- **动作**：读 `docs/philosophy.md` 六约束（单一数值源／恒定几何／档位制／两缓动按语义／分层叠加状态／克制与真实可达）与 `docs/anti-patterns.md` 反例库；列本项目界面清单，按内容浏览型／工具型／混合型标注。
- **产出**：范围声明一段（做什么、明确不做什么）＋六约束逐条的本项目落点注记。
- **自检**：范围声明能回答「最小可用面是什么」；六约束无一条「不适用且无替代方案」。

### 步 2｜建本项目 token 层

- **目标**：把体系词汇表落成本项目单一数值源，消灭散落字面量。
- **动作**：
  1. **语义键照搬**：键位体系沿用 `tokens/` 四件的 DTCG 分组——`color.surface.*`／`color.text.*`／`color.interaction.*`／`dimension.radius.*`／`motion.duration.*`／`motion.easing.*`／`typography.*`；不发明新组名，新场景需求先问「是不是既有组的别名」。
  2. **数值重推导**：颜色按项目品牌推导并做双主题对比度自检；圆角按两档判定——输入/动作＝控件档（示例值 4px，`dimension.radius.control`）、承载内容＝表面档（示例值 8px，`dimension.radius.surface`）；时长锚定三档（示例值 83/167/250ms，`motion.duration.*`）不新增档。
  3. **双主题同键位**：浅深两套值挂同一键名——DTCG 里原始值在 `color.light.*`／`color.dark.*` 两组、语义层为别名，深色解析＝别名路径 light→dark 替换（参照 `tokens/color.tokens.json`）；平台镜像同键位整本替换。
- **产出**：本项目 token 层与双主题载体（WPF＝常量类＋双字典，见 [wpf.md](wpf.md) §二；Web＝CSS 变量双主题，见 [web.md](web.md) §二）。
- **自检**：键名清单与 `tokens/` 分组逐组可对照；双主题键位 1:1；样式代码里零裸 hex/px/ms 字面量。

### 步 3｜搭单源镜像锁定测试

- **目标**：用测试兜住「UI 镜像 == 数值源」，漂移在提交前暴露而非上线后目检。
- **动作**：为 token 两条消费通道各写断言——镜像通道（资源字典/CSS 变量表）逐键等于数值源；直引通道（编译期绑定）断言取值点来源唯一；再加键数计数断言（新增键只改一侧即红）。骨架见 [wpf.md](wpf.md) §三。
- **产出**：可进 CI 的镜像锁定测试集。
- **自检**：改任一数值源值→测试红、改回绿；新增键未同步镜像→计数断言红。

### 步 4｜组件范式选型

- **目标**：从范式库选结构，不自创等价结构（自创＝未来的维护孤岛）。
- **动作**：按步 1 范围对照 `docs/patterns/` 各篇——分层状态卡片／快捷操作瓦片／瓦片网格／overlay 滚动条／对话框单壳／空状态／chip 过滤轨／贴边停靠／容器变换弹层／实验开关／阅读视图／设置信息架构；每项登记「入选/排除＋本项目变体」。
- **产出**：范式选型清单。
- **自检**：入选范式均有实现落点（页面/组件名可指认）；排除项与范围声明不矛盾。

### 步 5｜动效档位映射

- **目标**：全部动效收敛到「三档两缓动＋减动效退化」，杜绝第 4 档时长与散布曲线。
- **动作**：场景时长一律锚定三档或其别名（`motion.duration.*`，场景别名如 `motion.duration.hover-feedback`）；缓动按语义二选一（进入态减速 `motion.easing.enter`／离开态加速 `motion.easing.exit`）；编排值逐场景登记（交错步长 `motion.duration.stagger-step`、封顶 `motion.stagger.tile-cap`、不对称例外须有理由）；减动效退化口径成文——统一退化为快档纯淡入或立即定格，时序性延迟保留。
- **产出**：动效映射表（场景→档位/曲线/编排/退化行为四列）。
- **自检**：映射表无档位外数值；每条例外有登记理由；每个场景能指认自己的退化行为。

### 步 6｜反例库自查

- **目标**：把已知废弃做法挡在合并前（前人学费不重交）。
- **动作**：设计与实现对照 `docs/anti-patterns.md` 逐条过（第二数值源、阴影效果进文字子树、纯透明度隐藏、滚动条占布局宽、弹窗假圆角、快照引用、模式化交互、缓动散布、禁用散档……）；命中即改并记整改。
- **产出**：反例核对记录（条目×命中×整改）。
- **自检**：全部条目状态非「未看」；每处整改有对应测试或评审注记。

### 步 7｜双主题截图自检

- **目标**：用真实渲染验证「双主题同键位、结构零变化」。
- **动作**：浅/深两套全量截图；逐区域对照——布局与几何完全一致、只有色板换；状态层/阴影层/内容层各就各位；`assets/` 台账可作结构参照（看结构不看像素）。
- **产出**：双主题截图集＋逐张核对结论。
- **自检**：两套截图无结构差异；发现问题回步 2/4 修复后重截，不用截图工具「补救」。

### 步 8｜收尾验收

- **目标**：以清单关账，给项目留下可持续演进的接口。
- **动作**：过验收清单——数值唯一声明点／圆角两档判定／时长三档无未登记例外／缓动按语义且单点消费／分层状态表达／滚动条不占布局宽／弹窗单壳／空状态无行动号召／双主题活切换／关键指针路径经真实输入验证；把项目侧新增键位与例外登记进项目文档。
- **产出**：验收清单勾选记录＋移交注记（新键位/例外/已知妥协）。
- **自检**：清单全绿，或每处未绿项有登记理由与跟踪入口。

## 三、最小采用集（三个必做项）

只想投入两成成本先拿到大部分风格收益时，做这三件，其余步骤按需补：

1. **最小语义色板＋双主题同键位**（步 2 子集）：表面/文字/描边/强调/危险/悬停/选中约 12 键，浅深两套同键位整本替换；收益＝整体气质与完整暗色能力。
2. **动效只用三档两缓动＋减动效退化**（步 5 子集）：所有过渡取 `motion.duration.*` 三档、缓动按语义二选一、减动效统一退化到快档纯淡入；收益＝微交互手感立刻统一。
3. **分层状态卡片＋阴影隔离**（步 4 子集）：根/阴影层/内容层三层结构，阴影独立层不进文字子树；收益＝最显眼的组件质感与文字清晰度。

三项自检：色板无双源（锁定测试同步建）；动效无第 4 档；卡片文字在任意阴影配置下不发糊。
